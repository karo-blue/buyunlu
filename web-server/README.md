# 网页支付 API

此目录是原网页的账号与支付服务端源码，不包含生产配置、密钥、账号库或账本。适用仓库根目录的非商业使用许可。生产站点的商户接入不向 Fork 或其他部署授权。

使用 Node.js 24，运行 `npm ci --omit=dev --ignore-scripts` 和 `npm test`。服务默认只监听本机 `127.0.0.1:4180`，由自己的 HTTPS 反向代理对外提供 API。`H5_ORIGIN` 为后端来源；`H5_BASE_PATH` 为后端路由前缀；`H5_FRONTEND_URL` 为前端完整目录网址，必须以 `/` 结尾。同步返回前端，异步通知只发后端。

将 `.env.example` 复制到 Web 根目录之外，填入自己的配置，设为仅服务管理者可读。用 Node 的 `--env-file=/absolute/private.env` 加载。修改前端 `web/site.json` 的公开 API 地址并重新构建。不要上传私有配置或数据目录。

跨域时仅接受配置的前端 Origin，通过 CORS 暴露不透明会话令牌，不依赖第三方 Cookie；会话绑定签发来源，摘要和到期时间持久保存在数据目录的 sessions.json（权限600），不会记录原始令牌。有效期30天，活跃会话每24小时续期一次，重启后仍有效；退出撤销会话，邮箱验证前的旧会话会永久失效。账号、会话及账本应一起备份，禁止多个服务进程共享同一数据目录。新注册用户名为 3～24 位英文字母、数字或下划线，密码为 8～20 位；已有中文用户名和长密码仍可登录。登录支持用户名或已验证邮箱（邮箱不区分大小写），两种方式对应同一账号和余额，未验证的邮箱记录不能用于邮箱登录。账号密码使用 scrypt 摘要，注册须验证邮箱。SMTP 预检只验证连接和认证，不等于用户确认收到邮件。

`H5_ALIPAY_ENABLED` 默认关闭。实际已开通的手机/电脑网站支付分别配置 `wap` / `page`。`H5_ALIPAY_TEST_USERS` 非空时，仅指定且已验证邮箱的用户名能创建 1 元、10 张的测试订单；空值表示不限制测试账号，启用前应明确核验。

`H5_LEADERBOARD_URL` 指向已有排行榜服务。`GET /public/leaderboard`、`/public/tigerboard`、`/public/escapeboard` 允许未登录查看原有公共数据，只转发受限条数的读取请求，不转发用户指定的 clientId、邮箱、Cookie 或会话令牌。结局提交仍须通过原有认证接口，不会因查看榜单而上传本机成绩。

服务端确定金额和张数、验签并核对商户与订单，重复通知/查询不重复发卡。浏览器返回参数不能发卡。余额与消费请求保存在服务端，不能从本机免费卡或游戏存档导入。当前账本使用单进程 JSON 原子替换，禁止多进程并发写入同一目录；账本和账号应一起备份。示例不提供自动退款界面。

正式开通前由商户本人完成一次 1 元付款，验证 10 张到账、一次用卡剩 9 张，以及重复查单不增发。此步骤不得用模拟通知代替。接入资料见[支付宝官方 Node.js SDK](https://github.com/alipay/alipay-sdk-nodejs-all)。

邮箱验证码登录接口：`POST /login/email/send` 接收 `{email}`，仅向已注册且验证的邮箱发登录码，不自动注册；返回统一提示以减少账号状态泄露。`POST /login/email/verify` 接收 `{email,code}`，成功后为同一账号签发正常持久会话。6位码10分钟有效、单次使用，发送间隔60秒，按IP、邮箱和账号限流；错误5次后需重新发码。登录挑战与注册验证分开加盐摘要保存，成功后保留发送频率记录，删除验证码摘要。
